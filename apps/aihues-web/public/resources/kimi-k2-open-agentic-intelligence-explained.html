Kimi K2 Explained: Open Agentic Intelligence at Trillion Scale

Moonshot AI shipped a trillion-parameter open model that does not just answer questions. It uses tools, writes code, and finishes multi-step jobs. Here is how it works, in plain terms.

2026-06-258 min readAIHues Team

Source: Read the paper ↗ · Download PDF ↓

TL;DR

Kimi K2 is a Mixture-of-Experts language model with 1 trillion total parameters but only 32 billion active on any given token. That ratio is the whole trick: frontier capacity, mid-size inference cost.

It was pre-trained on 15.5 trillion tokens with a new optimizer, MuonClip, that ran the entire schedule with zero loss spikes. The team then taught it to act through large-scale agentic data and reinforcement learning.

The release is a non-thinking model, meaning it answers directly rather than emitting long visible reasoning. It still posts state-of-the-art open results on coding and agentic benchmarks, including roughly 65.8% on SWE-bench Verified.

Why it matters

Most of the loudest model releases of the past two years were closed. You could call the API, but you could not see the weights, fine-tune freely, or run the thing on your own hardware. Kimi K2 lands on the other side of that line: open weights, a published recipe, and a paper that walks through the parts that usually stay secret.

The more interesting word in the title is agentic. A chat model predicts the next sentence. An agentic model is trained to take actions, read what came back, and decide what to do next. That loop is what powers a coding assistant that edits a repo, runs the tests, and fixes its own failures. Kimi K2 was built for that loop from the start, not bolted on afterward.

So the contribution is twofold. There is the artifact, a capable open model you can actually download. And there is the method, a training stack stable enough to push a trillion parameters through 15.5 trillion tokens without the usual mid-run blowups. The second part is arguably more durable, because anyone can reuse it.

The architecture: a sparse trillion

A dense model lights up every parameter for every token. That gets expensive fast. A Mixture-of-Experts model splits the feed-forward layers into many small experts and routes each token to just a few of them. The model holds a huge amount of knowledge, yet only a slice fires at a time.

Kimi K2 takes that idea to a sharp ratio. The full network is a trillion parameters. For any single token, a router picks 8 experts out of 384, adds one shared expert that always runs, and activates about 32 billion parameters. You pay roughly the inference bill of a 32B model while reaching into a 1T knowledge store.

Component Value
Total parameters 1 trillion
Activated parameters per token 32 billion
Experts (selected per token) 384 (8) + 1 shared
Attention Multi-head Latent Attention (MLA)
Vocabulary 160K
Context length 128K tokens

High sparsity is a deliberate bet. More, smaller experts raise capacity without raising per-token compute, as long as the router stays balanced and training stays stable.

The catch with going this sparse

Pushing the expert count up is not free. Routing can collapse onto a few favorite experts, and very large attention layers tend to produce runaway logits that destabilize training. The architecture only pays off if the optimizer can hold a steady run for trillions of tokens. That is the problem the next section solves.

How it was trained: MuonClip

Large training runs fail in a boring, expensive way. Attention scores drift upward, a few logits explode, the loss spikes, and you roll back to a checkpoint and lose days. The bigger the model, the more often it happens.

Moonshot's answer is MuonClip. Start with the Muon optimizer, which is token-efficient but known to let attention logits grow unchecked at scale. Then add QK-Clip, a correction that rescales the query and key projection weights right at the source whenever a head's attention logit crosses a threshold. The cap is applied per head, so it only touches the heads that misbehave and leaves the rest alone.

MuonClip kept the full 15.5-trillion-token pre-training run free of loss spikes. No babysitting, no rollbacks, no restarts.

That stability is the quiet headline of the paper. A run that never spikes is a run you can plan around, and it means the sparse trillion- parameter design is actually trainable rather than just trainable on paper.

Teaching it to act

Pre-training gives a model knowledge. It does not teach the model to use a terminal. To get there, the team built a post-training stage in two parts.

First, large-scale agentic data synthesis. They generated tool-use trajectories across many simulated and real environments, so the model saw thousands of examples of calling a tool, reading the result, and choosing the next step. Second, a general reinforcement learning stage that blends two reward signals: verifiable rewards for tasks with a checkable answer, such as code that compiles and passes, and a self-critique rubric for open-ended tasks where there is no single right answer.

The verifiable-reward half is what sharpens the coding and math skills. The rubric half keeps the model usable on the fuzzy requests that fill most real conversations.

How it benchmarks

The headline numbers cluster around agentic coding and reasoning, which is where the training was aimed. The figures below are single-attempt (pass@1 style) scores reported for the Kimi K2 release.

Benchmark What it measures Kimi K2
SWE-bench Verified Real GitHub issue fixes ~65.8%
LiveCodeBench v6 Fresh competitive coding ~53.7%
AIME 2025 Hard competition math ~49.5%
GPQA-Diamond Graduate-level science ~75.1%
Tau2-bench Multi-turn tool use ~66.1%
MMLU Broad knowledge ~89.5%

Read these as a snapshot, not a leaderboard. Benchmark harnesses, prompt formats, and scoring change often. Treat exact percentages as approximate and re-check the paper for the conditions behind each number.

The pattern worth noticing: among open, non-thinking models, the coding and agentic scores are the standouts. SWE-bench Verified is the one to watch, because it asks the model to resolve actual reported bugs in real repositories, which is far closer to a developer's day than a puzzle dataset.

What it does not do

The release is a non-thinking model. It does not produce long chains of visible reasoning before answering, which is the technique many competing systems lean on for the hardest math and logic problems. For those narrow, deeply sequential tasks, a dedicated reasoning model can still pull ahead.

Agentic runs also have a cost profile. When a task needs many tool calls, token usage climbs, and the model can occasionally loop or take a longer path than a human would. None of this is a flaw unique to K2. It is the current shape of agentic systems, and the paper is candid about it rather than papering over it.

Why it matters for builders

If you are building on top of models, Kimi K2 is worth a serious look for tool-heavy and code-heavy workloads, where its training was focused and its open weights let you fine-tune without begging a vendor for access. The 32B-active design also means the inference economics are friendlier than the trillion-parameter label suggests, which matters the moment you move from a demo to a bill. The deeper lesson sits in the method: MuonClip shows that stability at scale is an engineering choice you can make on purpose, and that is the part of this paper the rest of the field will quietly borrow.
